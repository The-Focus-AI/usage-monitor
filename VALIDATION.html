04

1Password auto-discovery

Read thefocus vault, discover client SAs, find API keys. Injectable op CLI runner.

Flow

OP_SERVICE_ACCOUNT_TOKEN → op item list --vault thefocus
  → find API_CREDENTIAL items named "* service account token"
  → for each: op item get → extract credential + vault fields
  → for each client vault: op item list → match known env vars
  → return [{ name, vaultName, slug, serviceAccountToken, keys }]

Endpoints

05

Full auto-cycle + notifications

Discovery → check → store → notify. Per-client thresholds. Cron scheduler.

Cycle

runFullCycle():
  1. runDiscovery()            — 1Password or env var fallback
  2. syncFromDiscovery()       — upsert clients in DB
  3. checkClientKeys(keys)     — run all 14 providers
  4. store results in DB       — usage_checks table
  5. processNotifications()    — evaluate thresholds, send
  6. writeStatusFile()         — atomic JSON output

Notification thresholds

balance ≤ threshold_critical → 🚨 CRITICAL
balance ≤ threshold_warning  → ⚠️ WARNING
check failed                 → ❌ ERROR
else                         → ✅ healthy (no notification)

07

Status file output

Atomic JSON status file after each check cycle. Consumable by pi agent skills.

File format

{
  "checkedAt": "2026-05-15T03:00:00Z",
  "clients": [{
    "name": "Acme Corp",
    "slug": "acme-corp",
    "keys": [{
      "provider": "openai",
      "status": "success",
      "balance": 45.23,
      "spend": 12.50,
      "lastChecked": "2026-05-15T03:00:00Z"
    }]
  }],
  "summary": {
    "totalKeys": 12,
    "healthy": 10,
    "errors": 2,
    "critical": 1
  }
}

Config

STATUS_OUTPUT_PATH=/path/to/status.json   # default: ~/.usage-monitor/status.json
Atomic write: write to .tmp → rename (no partial reads)
Auto-creates directories if missing

Validate

Terminal
cat ~/.usage-monitor/status.json | jq '.summary'
# → {"totalKeys":14,"healthy":1,"errors":13,"critical":0}
